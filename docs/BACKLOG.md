# Backlog

Ideas and deferred work noted during phases instead of being built. Each item is reviewed with the owner before it is scheduled.

| #   | Idea                                       | Why / context                                                                                                                                                                                                                                                            | Noted in phase | Status |
| --- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------- | ------ |
| 1   | Reset the RTK Query cache on sign-out      | Per-user queries now exist (phase 3). They are keyed by uid and their listeners stop quietly on sign-out, but the old user's data stays in memory until the cache entry expires (about 60 s). Clear it when the uid changes, keeping the `authState` subscription alive. | phase-2        | idea   |
| 2   | Sign out of all devices                    | Needs refresh-token revocation, which requires the Admin SDK (no custom backend). "Sign out of all tabs" covers this browser only.                                                                                                                                       | phase-2        | idea   |
| 3   | Require a verified email in security rules | Verification is enforced in the UI only; adding `request.auth.token.email_verified` to rules would also block unverified API access. Google accounts are always verified.                                                                                                | phase-2        | idea   |
| 4   | Split the Firebase SDK chunk               | The shared Firebase chunk is about 800 kB before gzip; consider manual chunks for auth, firestore and storage.                                                                                                                                                           | phase-2        | idea   |
| 5   | Resize avatars client-side before upload   | Uploads are limited to 2 MB as-is.                                                                                                                                                                                                                                       | phase-2        | idea   |
| 6   | Net worth across currencies                | Phase 3 sums base-currency accounts and lists other currencies separately. Converting needs an FX rate source (manual rates or a public API) and a decision on which rate date to use.                                                                                   | phase-3        | idea   |
| 7   | Lock an account's currency once used       | The account form still allows changing the currency. Once transactions exist, changing it would misstate every amount; lock it (or offer a guided conversion).                                                                                                           | phase-3        | idea   |
| 8   | Restart live listeners after an error      | If a live `onSnapshot` listener fails mid-session (not at first load), the user gets a toast and must reload. Could resubscribe with backoff.                                                                                                                            | phase-3        | idea   |
| 9   | Emulator-backed Playwright tests in CI     | Phase 3 acceptance (accounts, categories, reorder, two tabs, offline sync) was driven in Chromium against the emulators by a local script; making it a CI job would need Java + emulators in the e2e job.                                                                | phase-3        | idea   |
| 10  | Delete accounts and categories             | Only archive/restore exists. Hard delete needs a rule for what happens to their transactions.                                                                                                                                                                            | phase-3        | idea   |

Status values: `idea`, `accepted`, `scheduled (phase-n)`, `rejected`.
